# Windows 网络变化恢复

## 需求与边界

Windows TUN 运行期间，有线、Wi-Fi、ZeroTier 地址、网段和路由变化后重新推断出口，保护本机地址和系统路由。保留现有配置、HTTP API、静态控制台和规则资源回退行为。

## 实现

- 网络地址和可用性事件合并后触发刷新，250 ms 防抖；2 秒周期校验补充路由与 DNS 变化检测。
- 以接口地址、前缀、DNS 和非自有路由生成有序快照。快照变化或自有路由丢失时推进网络版本，重新校验自有路由。失败项独立保留并重试。
- 自有路由记录前缀、接口索引、源地址、下一跳。删除前验证当前记录并保护本机地址；系统路由接管后取消所有权。未跟踪的历史缓存路由不再按 IP 模糊删除。
- 网络版本使直连成功缓存失效。新 TCP 连接使用更新后的源地址；直连源地址按目标查询。UDP 会话按源地址及网络版本重建。
- 自动路由模式重新校验上游绕行及 TUN 默认路由，刷新在线网卡 DNS 重定向，避免用拦截地址覆盖原始 DNS 备份。
- 刷新串行执行，异常记录后重试；停止服务先等待监控结束，再清理路由和设备。

## 验证与限制

回归测试使用模拟路由表验证副网卡接入、系统路由接管、目标变为本机地址、删除失败重试、缓存版本失效，以及后台异常重试和停止等待。单元测试不访问真实 TUN、管理员服务或实时网络。

CLI 必须编译通过，运行完整测试套件。本机只有 .NET 10 运行时，测试通过进程级 DOTNET_ROLL_FORWARD=Major 执行；目标框架仍为 .NET 8。

发布后需要手工验证 Windows 网络切换、DNS、上游代理和 ZeroTier RDP。已有 TCP 源 IP 消失时需由应用重连；本次不迁移已有 TCP 会话，也不自动修复旧版本已删除的系统本地路由。
